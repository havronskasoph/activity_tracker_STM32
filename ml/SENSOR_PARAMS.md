# Параметри сенсора для прошивки

Усе, що потрібно для налаштування збору даних з акселерометра на STM32, щоб дані відповідали
тому, на чому навчалася модель `st_ign_wl_24`.

Загальний опис ML-частини — у [README.md](README.md), результати оцінки —
у [results/RESULTS.md](results/RESULTS.md).

---

## Зведена таблиця

| Параметр | Значення | Коментар |
|---|---|---|
| **ODR (частота дискретизації)** | **26 Hz** | **Критично точно.** Препроцесинг (фільтр Butterworth) розрахований саме під 26 Hz. Інша частота зламає розділення «гравітація / динаміка» |
| **Full scale** | **±4 g** | |
| **Сенсор** | тільки акселерометр, 3 осі X/Y/Z | Гіроскоп моделлю **не використовується** |
| **Одиниці на вході моделі** | **m/s²** | Див. пояснення нижче |
| **Розмір вікна** | **24 відліки** (приблизно 0.92 с при 26 Hz) | |
| **Перекриття вікон** | **0%** (без перекриття) | Крок дорівнює довжині вікна |
| **Препроцесинг** | gravity rotation + suppression | Обовʼязково увімкнений |
| **Орієнтація плати** | не критична | Див. застереження нижче |

Форма входу моделі — `(24, 3, 1)`, FLOAT32.

## Хто саме робить конвертацію g у m/s²

Сама модель конвертацію **не виконує** — це робить код навколо неї:

- **У прошивці:** `application_code/sensing/STM32U5/Dpu/Src/preproc_dpu.c`
  - рядок 35: `#define AI_DPU_G_TO_MS_2 (9.8F)`
  - рядок 114: `float scale = CTRL_X_CUBE_AI_SENSOR_FS * AI_DPU_G_TO_MS_2;` — сирі дані
    масштабуються на `±4 g × 9.8`
- **У Python-пайплайні (навчання та оцінка):**
  `human_activity_recognition/tf/src/datasets/mobility_v1.py`, рядки 54–55 — дані з `.pkl`
  (збережені в `g`) множаться на `9.8`

Тобто у файлах датасету дані лежать у `g`, а на вхід моделі подаються в `m/s²`. Якщо пишеться
власний шлях подачі даних — конвертацію треба зробити самостійно.

## Орієнтація та кріплення плати

Жорстка орієнтація **не потрібна**: препроцесинг `gravity rotation` покадрово повертає систему
координат так, щоб гравітація дивилась уздовж осі Z, тому модель інваріантна до того, як
закріплена плата.

⚠️ **Виняток:** уникати положення, коли сенсор рівно перевернутий (гравітація вздовж **+Z**).
У цьому випадку поворот вироджується і обробляється окремою гілкою коду, не еквівалентною
коректному повороту.

Опорна (нульова) орієнтація, за якої поворот тотожний — гравітація вздовж **−Z** (−1 g).

## Порядок класів

Набори класів у двох датасетах **різні** і не взаємозамінні:

- `mobility_v1`: `[Stationary, Walking, Jogging, Biking]`
- WISDM: `[Jogging, Stationary, Stairs, Walking]`

Порядок класів критичний — він має збігатися з тим, що прописано в `class_names` конфігу
та в `CTRL_X_CUBE_AI_MODEL_CLASS_LIST` у прошивці, інакше підписи класів на платі будуть зміщені.

Для цільового застосування використовується модель, навчена на `mobility_v1` (4 класи з `Biking`,
без `Stairs`).

## Відповідні визначення в прошивці

Згенеровані значення в `ai_model_config.h`:

```c
#define CTRL_X_CUBE_AI_SENSOR_TYPE   (COM_TYPE_ACC)
#define CTRL_X_CUBE_AI_SENSOR_ODR    (26.0F)
#define CTRL_X_CUBE_AI_SENSOR_FS     (4.0F)
#define CTRL_X_CUBE_AI_PREPROC       (CTRL_AI_GRAV_ROT_SUPPR)
```
